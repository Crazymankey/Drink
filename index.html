n8n 自動化案例作品集

客戶情境 — 手搖飲連鎖品牌「茶語」

庫存見底前，先一步收到 LINE 提醒

多家分店的庫存記錄在 Google 試算表裡，過去得靠店主每天手動翻表格核對。這套流程改由系統每天自動檢查，只把真正需要補貨的品項整理成一則訊息，主動推播到店主的 LINE。

專案背景

人工翻表格，缺貨常常等到現場才發現

「茶語」有多家分店，庫存資料統一記錄在 Google 試算表中。分店一多，老闆很難每天逐一檢查每個品項是否低於安全存量，缺貨狀況往往是店員要用時才被發現，補貨永遠慢半拍。

目標是讓系統取代這件重複的檢查工作：每天定時掃過所有分店的庫存，自動抓出低於安全存量的品項，直接組成訊息送進老闆的 LINE，不需要再打開表格人工核對。

交付成果

每日補貨檢查流程

這是實際交付給客戶、每天自動運作的核心流程：讀取庫存 → 逐筆判斷 → 篩選需補貨項目 → 組成訊息 → 發送 LINE 通知。

01

讀取 Google Sheets 庫存資料

透過 Get row(s) in sheet 節點讀取當下所有分店的庫存紀錄。

02

逐筆判斷並篩選需補貨項目

用 Loop Over Items 搭配表達式（剩餘數量 < 10 則標記「需補貨」），再用 Filter 篩出真正需要處理的品項。

03

LINE 自動通知

篩選結果組合成一則完整訊息，透過 HTTP Request 呼叫 LINE Messaging API 推播給店主。

使用說明

老闆平常怎麼用這套系統

系統交付後，日常操作幾乎不需要額外學習，安全存量的調整也不需要動到 n8n 流程本身。

01

平常不用做任何事

排程時間一到，系統會自動檢查所有分店的庫存。沒有品項低於安全存量時，就不會發送任何通知，不用特地確認「今天有沒有跑」。

02

收到 LINE 通知後，照清單補貨即可

訊息會直接列出「哪家分店、哪個品項、剩餘數量」，照著清單安排補貨就好，不需要再另外打開試算表核對一次。

03

想調整補貨標準，直接改試算表就好

覺得某個品項的安全存量訂得太高或太低，打開 Google 試算表把數字改掉、存檔即可。下一次排程就會用新的標準去判斷，完全不需要碰到自動化流程的設定。

04

之後要加分店或加品項，也是同一招

在試算表裡新增一列資料，系統會自動一併讀取、一併檢查，不需要額外調整流程。

如果日後想調整發送時間、通知的人，或是加上其他功能，我可以協助修改。

開發輔助

測試資料寫入流程

此流程僅用於開發階段模擬「分店回報庫存」情境，將測試資料寫入 Google 試算表，方便驗證上方的核心流程邏輯。正式運作時不需要此流程，只需持續使用「每日補貨檢查」即可。

學習與技術重點

這個專案釐清的幾件事

  • 表達式模式（fx／紫色「=」）與純文字模式的差異，避免 {{ }} 被當成純文字輸出
  • Loop 迴圈的兩個輸出分支：Loop Branch（單筆處理）與 Done Branch（彙總結果）
  • 用 $input.all() 搭配 .map() / .join()，將多筆資料彙整成單一文字訊息
  • JSON Body 含換行字元時，改用 JSON.stringify() 表達式，避免「Bad control character」格式錯誤
  • 用 Header Auth 憑證機制保護 LINE Channel Access Token，避免明碼暴露在畫面上
  • 釐清「開發測試用流程」與「正式交付流程」的界線，只需交付核心運作邏輯
